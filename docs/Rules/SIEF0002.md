# SIEF0002 - Synchronous EF Core call detected

## Explanation

Using synchronous methods on Entity Framework Core queries can block threads and lead to performance issues. This analyzer detects synchronous methods called on `IQueryable` or `DbSet` and suggests using the async alternative instead.

Note that synchronous methods called inside expression trees (e.g., within a `Where` lambda) are not flagged, as they are part of the expression definition and not executed synchronously.

## Code example

````csharp
using var ctx = new TestContext();

// Non-Compliant - synchronous methods
ctx.Entities.ToList();
ctx.Entities.Where(x => x.Id > 0).First();
ctx.Entities.Count();
ctx.Entities.Any();

// Compliant - async alternatives
await ctx.Entities.ToListAsync();
await ctx.Entities.Where(x => x.Id > 0).FirstAsync();
await ctx.Entities.CountAsync();
await ctx.Entities.AnyAsync();

// Compliant - synchronous method inside expression tree
ctx.Entities.Where(e => ctx.ProjectionEntities.Any(p => p.Id == e.Id)).ToList();
````

## Coverage

The following synchronous methods are detected by the analyzer:

- `All`
- `Any`
- `AsEnumerable`
- `Average`
- `Contains`
- `Count`
- `ElementAt`
- `ElementAtOrDefault`
- `Find`
- `First`
- `FirstOrDefault`
- `Last`
- `LastOrDefault`
- `LongCount`
- `Max`
- `MaxBy`
- `Min`
- `MinBy`
- `Single`
- `SingleOrDefault`
- `Sum`
- `ToArray`
- `ToDictionary`
- `ToHashSet`
- `ToList`
- `ToLookup`

## Configuration

This analyzer is always enabled and does not have configuration options.
